✨ What This Website Can Do — Architecture & Guide

University Examination Timetabling Optimization Research Engine

🎯 System Overview & Capabilities

This platform solves the Examination Timetabling Problem (ETP) — a challenging NP-hard combinatorial optimization challenge in higher education. The system models multi-campus venues (e.g. UMP Gambang and Pekan campuses) across 30 discrete timeslots (10 examination days with Morning, Afternoon, and Evening slots), allocating exams to venues while guaranteeing zero student clashes and satisfying strict university constraints.

📝 7 Hard Constraints (Feasibility Criteria)

ID Constraint Mathematical Formulation & Meaning
H1 Clash-Free Schedule No student may be scheduled for two exams concurrently in the same timeslot: ∑ x_it ≤ 1 for conflicting exams.
H2 Single Assignment Every registered course exam must be scheduled exactly once: ∑_t x_it = 1 for all exams i.
H3 Room Capacity Total student seating allocated cannot exceed the room's physical capacity: ∑ s_i × y_ir ≤ C_r.
H4 Room Availability A venue can host at most one exam event per timeslot without double-booking.
H5 Campus Scope Courses offered in Gambang must be assigned to Gambang rooms; Pekan courses to Pekan rooms.
H6 Split Coincidence Sync Common faculty subjects (e.g., G0002 & P0002) must sit concurrently in the exact same timeslot: period(i) == period(j).
H7 Large Exams Early Massive courses (>400 students) must be placed within early timeslots 1–10 to avoid grading and logistical delays.

⚖️ 4 Soft Constraints (Quality Objectives)

ID Soft Objective Penalty Calculation
S1 Carter Spreading Minimizes student back-to-back exam fatigue. Proximity weight w(Δ) = 2^(5 - Δ) for exams with period gap 1 ≤ Δ ≤ 5.
S2 Building Distance When an exam splits across multiple venues, penalizes inter-building distances using the distance matrix D_rp.
S3 Split Minimization Penalizes splitting a course across multiple rooms unless physical capacity dictates it.
S4 Uniform Duration Avoids placing exams with different time limits (e.g., 90 min vs 180 min) into the same hall.

⚡ Two-Phase Solver Engine

Initial Phase (Constructive Graph Heuristics)
  • Largest Degree (LD): Prioritizes exams with highest conflict edge count.
  • Largest Enrollment (LE): Prioritizes exams with largest student registration.
  • Largest Weighted Degree (LWD): Prioritizes exams by total student clash weights.
  • Saturation Degree (SD LD / SD LE / SD LWD): Dynamically orders exams by remaining available timeslots.
Improvement Phase (Metaheuristics)
  • Hill Climbing Move (HC Move): Single exam re-assignment neighborhood search.
  • Hill Climbing Swap (HC Swap): Pairwise period exchange neighborhood search.
  • Late Acceptance HC (LAHC): Accepts moves comparing against a cost list L_fa steps prior.
  • Step Counting HC (SCHC): Updates the reference acceptance cost every L_s iterations.

🚀 Quickstart Guide

  1. Choose a Dataset: Use the built-in benchmark datasets or upload your 7-file institutional package.
  2. Generate Conflict Matrix: Verify student clash counts, density, and export CSV if needed.
  3. Set Constraints: Adjust hard/soft flags and parameters (max iterations, list length).
  4. Run Initial Phase: Pick an initial algorithm (e.g., LD) to generate a feasible seed timetable.
  5. Run Optimization: Pick a metaheuristic (e.g., LAHC or HC Move) to drive down soft penalty.
  6. Inspect Matrices & Grid: Open Xit, Yir, or Zrt views, and filter the final schedule DataGrid.
